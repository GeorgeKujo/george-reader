# GeorgeReader

九条丈二の記事リンクを自動収集するPWA（v0.6.1）。iPhone Safariでホーム画面に追加できます。本文の転載はせず、各媒体の公式ページで開きます。

GitHub Pages: Settings → Pages → Deploy from a branch → main / (root)。

## 自動更新

`Collect articles` Actionsが6時間ごと（日本時間 03:17 / 09:17 / 15:17 / 21:17 頃、GitHub側の遅延あり）に実行されます。Actions画面から手動実行もできます。標準Pythonのみを使用し、外部サービス登録・秘密鍵は不要です。

- アゴラ：九条丈二の著者ページ。記事カード内の著者リンクも照合します。
- note：`g_kujo_ir` の公開RSS。
- Yahoo!ニュース：公開検索の候補から記事の構造化データで著者名を照合します。検索や掲載期限、取得制限により全記事を網羅するものではありません。

`data/articles.json` にタイトル・URL・公開日、媒体別の取得状況と最終成功時刻を保存します。本文は保存しません。同一URLを統合し、新しい順で表示します。転載は別媒体のリンクとして残します。RSSや著者一覧に出なくなった過去記事は保持しますが、初回から全履歴を取得する機能はありません。

一部媒体の取得失敗時も保存済みの記事を維持し、アプリに媒体ごとの取得状況を表示します。全媒体失敗時はActionsを失敗にし、診断用JSONを成果物に残します。

main上でのみJSONをコミットし、既存のブランチ方式のPagesビルドを明示的に要求します（ActionsによるコミットだけではPages更新が始まらないため）。公式サイトのリポジトリ・DNS・CNAME・Pages設定は変更しません。

## PWAと端末データ

起動時・再表示時・「一覧を更新」でJSONを取得します。通信できない時はService Workerのキャッシュを使用します。v0.3の保存キーを維持し、既読・お気に入りと、過去に登録した記事を引き継ぎます。手動記事登録は廃止し、記事は自動収集します。自動収集した記事を削除すると、その端末では以後非表示になります。JSONバックアップと復元も利用できます。

## 検証

```sh
python -m unittest discover -s tests
node --test tests/app.test.cjs
python scripts/collect.py
```


## v0.5: 過去記事・関連表示

アゴラの著者ページは「次のページ」を最大10ページまで順に取得します。途中の取得に失敗した場合は取得できた分を保存し、画面に一部未取得と表示します。noteは公開RSSの掲載範囲、Yahoo!ニュースは公開検索の範囲に限られます。

表記を正規化した見出しが一致する別媒体の記事を「同じ見出しの記事」として相互に表示します。Yahoo!ニュースの既知の著者・配信元の接尾辞だけを除外して比較し、似ているだけの見出しは関連付けません。本文同一の保証ではないためURLは統合せず、既読・お気に入りも各リンクごとに保持します。

## 一括既読とYahoo!ニュース

「全て既読にする」は検索・媒体の絞り込みに関係なく、非表示にしていない全登録記事を既読にします。お気に入りと削除済み記事の設定は維持し、次回追加される記事は未読になります。

Yahoo!ニュースのリンクと自動収集には、九条丈二の指定検索URL（`https://news.yahoo.co.jp/search?p=%E4%B9%9D%E6%9D%A1%E4%B8%88%E4%BA%8C&ei=utf-8`）を使います。

## v0.6: 媒体をまとめた記事カード

収集データの関連URL（正規化した見出しの一致）を使い、同じ記事の各媒体版を1枚のカードにまとめます。似た見出しだけではまとめません。本文の同一性を保証するものではありません。

カード内で読む媒体を選択できます。開く操作と既読ボタンはカード内の全URLを既読にし、お気に入り・解除・削除もカード単位です。既存のURL別データは移行時に書き換えず、お気に入りは1媒体でも設定済みなら表示、既読が混在する場合は「一部既読」と表示します。未読フィルターには未読URLが残るカードが表示されます。媒体や検索の絞り込みでも、カード内の媒体リンクは全て表示します。件数はカード単位、更新情報の収集件数はURL単位です。バックアップは従来どおりURL単位で保持します。
